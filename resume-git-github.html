Git & GitHub

Les fondamentaux du contrôle de version : du premier commit local jusqu'à la pull request en équipe.

01

Git vs GitHub

Git est le logiciel de contrôle de version, installé en local, qui suit l'historique de tes fichiers. GitHub est une plateforme en ligne qui héberge des dépôts Git et ajoute la collaboration (pull requests, issues). Git fonctionne sans GitHub — l'inverse n'est pas vrai.

02

Architecture : local vs distant

  • Working directory — tes fichiers tels que tu les modifies.
  • Staging area — les changements sélectionnés pour le prochain commit.
  • Dépôt local (.git) — l'historique enregistré sur ta machine.
  • Les branches — pour teste des nouvelles fonctionnalites.
  • Dépôt distant (remote / GitHub) — la copie partagée en ligne.
03

Configuration & initialisation

$ git config --global user.name "Ton Nom"
$ git config --global user.email "ton@email.com"
$ git init # initialise un dépôt local
$ git clone <url> # copie un dépôt distant
04

Le cycle status → add → commit

$ git status
$ git add fichier.txt # un fichier précis
$ git add . # dossier courant
$ git add -A # tout le dépôt
$ git reset fichier.txt # retirer du staging
$ git commit -m "message"

Pour annuler le dernier commit : git reset HEAD~1 (les changements reviennent en staging ou en working dir selon --soft / --mixed / --hard).

05

Supprimer / arrêter de suivre

  • git rm fichier — supprime du disque et du suivi.
  • git rm --cached fichier — arrête le suivi mais garde le fichier (utile avec .gitignore).
06

Historique

  • git log — historique des commits (auteur, date, hash, message).
  • git diff — différences entre commits, staging, working dir.
07

Branches

Une branche est une ligne de développement indépendante (main est souvent la branche principale).

$ git branch nouvelle-fonctionnalite
$ git checkout nouvelle-fonctionnalite
$ git checkout -b nouvelle-fonctionnalite # créer + basculer
$ git branch --show-current
$ git branch -l # voir la liste des branches
$ git merge nouvelle-fonctionnalite $ git log --oneline # voir tous l'historique des commits avec leurs id's
$ git checkout id-commit creer une branche tomporaire pour qu'on puisse retourner a cette commit

Conflits de fusion : Git ne peut pas toujours fusionner automatiquement deux modifications sur les mêmes lignes. Il faut éditer manuellement les marqueurs de conflit dans les fichiers concernés, puis add + commit.

08

Le dépôt distant

CommandeEffet
git pushEnvoie tes commits locaux vers le distant
git push origin branchEnvoie tes commits d'une branche
git fetchRécupère les changements distants sans les fusionner
git pullÉquivaut à fetch + merge
09

Annuler & mettre de côté

  • git restore fichier — annule les modifications locales non commitées.
  • git stash / git stash pop — met de côté un travail non fini, puis le récupère.
  • git revert <commit> — annule un commit en créant un nouveau commit inverse (sûr sur historique partagé).
  • git rebase — réécrit l'historique pour le linéariser (à éviter sur des branches déjà partagées).
10

Pull Requests & collaboration

Une Pull Request (PR) propose de fusionner une branche dans une autre (souvent une feature branch → main), avec revue de code et vérifications automatiques avant fusion.

Workflow typique : branche → commits → push → PR → review → merge.
