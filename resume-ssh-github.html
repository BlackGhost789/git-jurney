🔑 Authentification SSH avec GitHub

📖 Définition et but

L'authentification SSH est une méthode qui utilise une paire de clés cryptographiques (une privée gardée sur ta machine, une publique donnée à GitHub) pour prouver ton identité, au lieu d'utiliser un identifiant et un mot de passe classiques.

Le client genere une paire de cle (privee et publique), le client garde son cle publique chez lui, dans l'etape d'etablissement de connexion le serveur va proceder a l'authentification, d'abord il va chiffrer un string challenge avec la cle pub du client et l'envoyer chez lui , if he pu de la dechiffrer il va la lui transmettre => challenge accepte et la connextion etablie.

Le but principal : remplacer l'authentification par mot de passe (que GitHub n'accepte d'ailleurs plus pour git push/git pull en HTTPS) par une méthode plus sûre et plus pratique. Une fois la clé configurée :

  • Plus besoin de taper ton mot de passe (ou un token) à chaque push/pull
  • La clé privée ne quitte jamais ta machine — seule la clé publique est partagée
  • Beaucoup plus difficile à intercepter ou à deviner qu'un mot de passe
  • Tu peux révoquer une clé sur GitHub sans changer ton mot de passe de compte
1 Générer une clé SSH 
ssh-keygen -t rsa -b 4096 -C "comment"

Crée une paire de clés : une privée (secrète) et une publique (.pub).

2 Démarrer l'agent SSH 
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

L'agent garde ta clé en mémoire pour éviter de retaper la passphrase à chaque fois.

3 Ajouter la clé publique sur GitHub 
cat ~/.ssh/id_ed25519.pub

Copier le résultat → GitHub → Settings → SSH and GPG keys → New SSH key.

4 Tester la connexion 
ssh -T git@github.com

Réponse attendue : Hi username! You've successfully authenticated...

5 Utiliser une URL SSH pour le remote 
git remote set-url origin git@github.com:user/repo.git

Sans ça, Git continue d'utiliser HTTPS et redemande identifiant/mot de passe.

💡 À retenir

  • ssh -T git@github.com teste seulement l'authentification, pas le remote d'un repo précis.
  • git remote -v permet de vérifier si le remote est en HTTPS ou en SSH.
  • Une fois configuré, plus besoin de mot de passe pour git push / git pull.
